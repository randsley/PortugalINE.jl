Indicators

PortugalINE.Indicators — Module

The INE indicator API: metadata, data, and the catalogue.

Three endpoints, all under https://www.ine.pt, all returning UTF-8:

endpointwhat it giveshere
json_indicador/pindicaMeta.jspan indicator's dimensions and their codesindicator_metadata
json_indicador/pindica.jsp?op=2the observationsindicator_data
xml_indic.jspthe catalogue, including each indicator's finest geographycatalogue

Why the catalogue is worth having

The catalogue carries <geo_lastlevel>, the finest geographic level an indicator is published at. That answers "can I get this by municipality?" without downloading the indicator and counting codes, which is how the question otherwise has to be answered — one request of tens of kilobytes per candidate. Of the 326 indicators in INE's main group on 2026-11-06, 98 reached Município and 17 Freguesia; since a freguesia is inside a municipality, 115 were usable here. On 2026-11-26 the group held 309 and 99: it changes, and indicators leave it without being withdrawn. ismunicipal applies that reasoning, and also absorbs INE's inconsistent spelling of its own levels (both NUTS III and NUTS 3 occur).

The main group is not all of INE: indicator 0014581 is published to Município and does not appear in the group listing at all. So 115 is a floor and not a census, catalogue is a cheap first pass rather than an authority, and catalogue_entry is how a code the group omits gets checked.

The group catalogue ignores lang for titles

xml_indic.jsp?opc=3 localises theme and subtheme and nothing else. All 326 titles come back identical under lang=EN and lang=PT, and all 326 are Portuguese; all 326 themes differ between the two. That was measured by fetching both and comparing, not inferred. So searching the group catalogue for "purchasing power" finds nothing and "poder de compra" finds the indicator, whatever language was passed.

The single-indicator call opc=1 does honour lang: the same indicator's title is Per capita purchasing power through catalogue_entry and Poder de compra per capita through catalogue. Search the group catalogue in Portuguese, or on theme, which is localised; take an English title from catalogue_entry once the code is known.

Three things the API does that will catch you

valor is a string. A row reads {"geocod":"3003106","geodsg":"Porto Moniz","ind_string":"61,78","valor":"61.78"}. valor is the machine form with a decimal point, ind_string the localised display form with a comma. This module parses valor and ignores ind_string; reading the latter as a number silently loses the fractional part in any locale that treats a comma as a separator.

Dados is keyed by the period's label, but Dim1 takes its code. The 2022 annual slice of indicator 0008074 is requested with Dim1=S7A2022 and comes back under the key "2022". Passing "2022" as the filter is rejected by INE with "Code(s) in Dim1 not valid for the indicator"; passing "S7A2022" and then looking for a "S7A2022" key finds nothing. period_code converts a label to a code from the metadata, and indicator_data accepts either.

Failure arrives with HTTP 200. An unknown indicator code returns {"Sucesso":{"Falso":[{"Msg":"...","Cod":"1"}]}} and status 200. Every entry point here checks Sucesso and throws INE's own message, so a typo surfaces as an error rather than as an empty table.

Caching

Responses are cached on disk, keyed by URL, because the API is slow and the answers change a few times a year. A body is cached only after it has parsed, since INE reports failure with HTTP 200 and a cached failure would be returned on every later call. Reset connections, HTTP 429 and 5xx, and bodies of the wrong shape are retried after the pauses in RETRY_DELAYS; an INE refusal is not. See ine_cache_dir to find or relocate the cache and clear_ine_cache! to drop it; pass cache = nothing to any call to bypass it.

PortugalINE.Indicators.INE_ATTRIBUTION — Constant
INE_ATTRIBUTION

The attribution INE's reuse terms require. Data from Statistics Portugal is open for reuse, commercial use included, under EU Directive 2019/1024; INE retains copyright and the single condition is that the source be cited. ine_citation builds the sentence with the indicator codes and the extraction date filled in, which is what the condition actually asks for.

One dimension of an indicator. number is the Dim<n> the API expects: 1 is always the reference period and 2 is always geography. categories lists the admissible codes.

PortugalINE.Indicators.DimensionCategory — Type
DimensionCategory

One admissible value of a dimension: the code to send as a filter (INE's cat_id, which is also what the data rows carry), the label INE displays, and its depth in the dimension's own hierarchy (level 1 is the root, so for geography level 1 is Portugal and level 5 is a municipality).

PortugalINE.Indicators.Indicator — Type
Indicator

An indicator's metadata, as returned by pindicaMeta.jsp. dimensions is what makes a data request constructible: it names every filter the indicator accepts and every code each filter will take.

source
PortugalINE.Indicators.IndicatorData — Type
IndicatorData

Observations, with the provenance needed to cite them. table is a NamedTuple of equal-length vectors, which is already a valid Tables.jl column table, so DataFrame(d.table) works without this package depending on either DataFrames or Tables.

Columns are always period, geocod, geodsg and value, in that order. value is Union{Float64, Missing}: INE suppresses some cells, and those arrive as missing rather than as a sentinel number. There is no unit field, because the data endpoint does not return one; the unit is indicator_metadata's unit. An indicator with dimensions beyond period and geography adds dim_<n> and dim_<n>_label for each.

The request is recorded with the data, because the figures depend on it: language, the dimensions filter that was sent (Dict(3 => "T") is "both sexes" in the Census 2021 indicators, and without it a column cannot say what it holds), and the url fetched. A cached response carries the URL it was cached under, which is the same thing.

PortugalINE.Indicators.cache_max_age — Method
cache_max_age() -> Float64

How old, in seconds, a cached response may be before it is fetched again: ENV["PORTUGALINE_CACHE_MAX_AGE"], or Inf. Every fetching function also takes max_age to override it per call.

The default is never to expire, deliberately: a cache seeded with cache_response! is how an extract is frozen so a published figure can be regenerated, and expiring it would silently replace the archived figures with INE's revised ones. Set a finite age to follow INE's revisions instead. When a stale response cannot be refreshed (INE down, or throttling), it is returned with a warning rather than an error. A response's own date is extracted on IndicatorData and Indicator, which INE stamps.

PortugalINE.Indicators.cache_response! — Function
cache_response!(path, kind, varcd = nothing; language = "EN", period = nothing,
                dimensions = Dict(), dir = ine_cache_dir()) -> String

Put a saved INE response into the cache, as though it had just been fetched, and return the cache file it was written to. kind is :metadata, :data or :catalogue; path is the file holding the response body, or the body itself.

This is how an extract gets frozen. A result that has to be reproducible — a paper's table, a dataset shipped with a package — depends on an API whose answers are revised, so archive the response bodies, seed them here, and every later call returns the archived figures with the network untouched. It is also how this package's own tests run offline.

period must be the code ("S7A2023"), not the label, because that is what goes in the URL the cache is keyed by.

PortugalINE.Indicators.catalogue — Method
catalogue(; language = "EN", cache = ine_cache_dir(), timeout = 300,
          max_age = cache_max_age())

Every indicator in INE's main group, as CatalogueEntry values. One request of roughly 500 kB, against one request per indicator for the same information.

The group is not exhaustive – 0014581 is a municipal indicator that is not in it – so a code absent from this listing is not an unpublished code. Look it up with catalogue_entry before concluding anything.

language affects theme and subtheme only. Titles, descriptions and keywords arrive in Portuguese whatever is passed, which is INE's behaviour and not a choice made here – see the note in this module's documentation. Search accordingly, and use catalogue_entry for an English title.

cat = catalogue()
length(cat)                                  # 326
count(ismunicipal, cat)                      # 115
search_catalogue(cat, "poder de compra"; municipal_only = true)
catalogue_entry("0014580").title             # "Per capita purchasing power"

PortugalINE.Indicators.indicator_data — Method
indicator_data(varcd; period = nothing, dimensions = Dict(),
               language = "EN", cache = ine_cache_dir(), timeout = 300,
               max_age = cache_max_age())

Fetch observations as an IndicatorData.

period filters Dim1 and may be a code ("S7A2023"), a label ("2023"), a vector of either, or :all; a label or :all costs one extra metadata request. dimensions filters the rest, as Dict(3 => "T") for Dim3=T. Filtering matters: an unfiltered multi-dimensional indicator is every period times every category, which for some indicators is tens of megabytes.

d = indicator_data("0014580"; period = "2023")
length(d)                        # 347 geographic units
d.table.value[1]                 # 61.78
d = indicator_data("0008074"; period = "2022", dimensions = Dict(3 => "T"))

Omitting period returns only the latest period, not every period: that is INE's default, measured on 2026-11-26 for four indicators (0012748 gave 2024 of 2018-2024; 0008234 gave 2023 of 2014-2023). For several periods in one request pass a vector, period = ["2018", "2019"] (labels or codes), which is sent as Dim1=S7A2018,S7A2019, or period = :all for every period the metadata lists. The period column then distinguishes them.

PortugalINE.Indicators.ismunicipal — Method
ismunicipal(e::CatalogueEntry) -> Bool

Whether the indicator is published at municipal level or finer, which is the condition for building a municipal weights matrix over it.

geo_lastlevel names the finest level available, so Freguesia counts: a freguesia is inside exactly one municipality, so the data aggregates up. Levels coarser than a municipality do not, whatever they are called — and INE calls NUTS III both NUTS III and NUTS 3 in the same document, which is why this is a function rather than a string comparison at the call site.

source
PortugalINE.Indicators.municipal_values — Method
municipal_values(d::IndicatorData; period = nothing) -> NamedTuple

Reduce an IndicatorData to the municipal rows, keyed by DICO and sorted by it, which is the ordering the weights files from PortugalINE.Boundaries use. The result is a column table with dico, geocod, name and value.

geocod is kept alongside the DICO because it carries the NUTS vintage the figures were published on, and that is not cosmetic: the same municipality has one NUTS code under NUTS 2024 and another under NUTS 2013. The DICO is stable across both, which is why it is the key and the NUTS code is only a record of where the figure came from.

Non-municipal rows are dropped: an INE geography response is a hierarchy, so the 347 rows of indicator 0014580 are 308 municipalities plus country, NUTS I, NUTS II and NUTS III aggregates, and summing the column would double-count Portugal four times over. Suppressed cells stay as missing rather than being dropped, so the length is the municipality count and a caller can see what is absent.

With more than one period present, period is required.

PortugalINE.Indicators.parish_values — Method
parish_values(d::IndicatorData; period = nothing) -> NamedTuple

As municipal_values, for the parishes (freguesias): the rows keyed by DICOFRE and sorted by it, as a column table with dicofre, geocod, name and value. Both INE forms are read: the 9-character code with its NUTS III prefix, and the bare 6-digit DICOFRE of the Census 2021 indicators.

INE publishes its parish figures on the parish map of the 2013 reform (3,092 parishes, 2,882 on the mainland), up to the 2024 reference period. The parishes restored in 2025 are on CAOP2024.1 and later, not on this map, so join these values to CAOP2024 or earlier.

A cell INE suppresses stays missing. For some indicators that is most of the country: the median declared income net of tax (0012757) has a value for 735 of the 2,882 mainland parishes in 2024, while the mean gross declared income (0012748) has all 2,882.

PortugalINE.Indicators.parse_value — Method
parse_value(x) -> Union{Float64, Missing}

Parse INE's valor, which arrives as a string with a decimal point, as null, or absent. Anything unparseable becomes missing rather than an error: INE suppresses cells for confidentiality and marks them in several ways, and a suppressed cell is a fact about the data, not a malformed response.

PortugalINE.Indicators.period_code — Method
period_code(ind::Indicator, period) -> String

Translate a period label into the code Dim1 expects, which is the trap this API sets most often: the metadata for an annual indicator lists its 2022 period as code S7A2022 with label 2022, the filter must carry the code, and the returned data is keyed by the label.

A value that is already a code passes through, so this is safe to apply twice. Anything matching neither is refused with the admissible labels listed.

PortugalINE.Indicators.search_catalogue — Method
search_catalogue(entries, text; municipal_only = false) -> Vector{CatalogueEntry}

Catalogue entries whose title, theme, subtheme, description or keywords contain text, ignoring case and accents, so "municipio" finds "Município". With municipal_only, restrict to indicators ismunicipal accepts.

Searching a catalogue listing means searching Portuguese titles, because that endpoint returns Portuguese titles under either language. theme and subtheme are localised and are searched too, so an English theme name works on an English listing.

Retries

Not exported: set it to zeros in tests, or to longer delays for a bulk build.

PortugalINE.Indicators.RETRY_DELAYS — Constant
RETRY_DELAYS

The pauses, in seconds, before the second, third and later attempts at an INE request. INE resets connections under load, so a failed connection, an HTTP 404, 429 or 5xx (INE answers 404 for valid codes when throttling), or a body of the wrong shape is retried after each of these; anything else, an INE refusal included, is thrown at once. Set PortugalINE.Indicators.RETRY_DELAYS[] = Float64[] to make one attempt only.
