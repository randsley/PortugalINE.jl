Panels

PortugalINE.Panel — Module

Panels: the same units over several periods, with one weights matrix.

A cross-section cannot tell a spatial lag from spatially correlated errors; repeated observations of the same units can. join_panel builds that: units present in the boundaries and in every indicator in every period, a value matrix (units x periods) per indicator, and one contiguity structure over the units. The geometry is fixed, so W is the same in every period, and that only holds if the units are: a unit that exists in some periods and not others is dropped, not carried with gaps in its geometry.

Two parish maps

INE publishes its parish figures on the 2013 map, but some indicators list the units of both maps: the area indicator 0011866 carries 3,184 mainland codes, the 2,882 of 2013 and the 302 parishes restored in 2025, the latter with no value before 2025. A unit with data and no boundary that holds no value in any period used is a listing of the other map's units, not a coverage gap, and is counted apart (dropped(p).empty) so the real gaps stand out. A unit with a boundary and a value in the extract but missing from another extract or period is a real gap, and is named.

Missing values

Units are kept whatever their values; a suppressed cell stays missing in its column. panel_matrices then keeps the units complete in every column and period it is asked for, and rebuilds W over them, for the same reason model_matrix does: a standardised matrix is valid only for the units it was computed over.

PortugalINE.Panel.join_panel — Method
join_panel(b::MunicipalBoundaries, specs...; periods, criterion = :queen) -> PanelDataset

Join indicators over several periods (labels, such as ["2018", "2019"]) to boundaries, keeping the units present in the boundaries and in every indicator in every period. Each spec is :column_name => data, where data is one IndicatorData holding all the periods (an unfiltered request) or a vector of them (one request per period). A column holds one indicator with one dimension filter, so its periods are comparable.

b   = read_caop_geojson("caop2024_freguesias.json"; level = :parish, edition = "CAOP2024")
inc = indicator_data("0012748")                                # all periods
bir = indicator_data("0008234"; dimensions = Dict(3 => "T"))   # both sexes
p   = join_panel(b, :income => inc, :births => bir; periods = string.(2018:2023))
m   = panel_matrices(p, :births, :income)

PortugalINE.Panel.panel_matrices — Method
panel_matrices(p, y::Symbol, xs::Symbol...; periods = p.periods,
               standardize = true, intercept = false)

What a spatial panel estimator needs: (y, X, W, keys, periods, N, T, xnames, dropped), over the units with a value in y and every x in every period used.

y and the columns of X are stacked period by period: the first N entries are period 1 for every unit in keys order, the next N period 2, and so on, which is the order kron(I(T), W) multiplies. W is N x N, rebuilt over the surviving units and row-standardised unless standardize = false.

PortugalINE.Panel.write_panel — Method
write_panel(dir, p; name = "panel", gal = true, centroids_file = true,
            coordinate_names = ("lon", "lat")) -> Vector{String}

Write the panel as long CSV, one row per unit and period, ordered by period and then by key (the stacking panel_matrices uses), plus the GAL file, the centroids and a provenance file. The GAL and centroid files have one row per unit, in key order, because the geometry does not change between periods.
